# Publicación automática de narrativa
El usuario autoriza publicar automáticamente las actualizaciones de narrativa integradas en la PWA, tras validación. El hook local post-commit, limitado a feature/narrative-coordination-20261124, invoca node vault-site/scripts/publish-narrative.mjs --auto al cambiar contenido publicado del libro, diálogo, arte o datos narrativos. No publica borradores de Library, expedientes privados ni ramas sin integrar. El motor conserva la autoridad de estado.
El script toma una instantánea exacta del commit, reconstruye actividad y valida la bóveda, verifica sintaxis, sincroniza GitHub sin force push, publica un canal candidato, verifica versión y rutas HTTP y promueve a live si no hubo otro release durante el proceso. Versiona PWA y service worker para detectar actualización. Si falla una validación o hay divergencia, se detiene: no hay promoción. No sustituye revisión de canon ni pruebas funcionales de campaña.
Diagnóstico: node vault-site/scripts/publish-narrative.mjs --check (sin publicar); reintento: node vault-site/scripts/publish-narrative.mjs. Solo en la rama coordinada. El disparador se ejecuta en SEBASU con autenticación Firebase CLI; no es CI remoto ni un vigilante de Library. Otros equipos deben usar la misma rama y mecanismo, o reconciliar una publicación externa antes de continuar. No se publica el registro privado de once ramas sin integración autorizada. 

Las modificaciones de componentes y diseños en public/dm/libro/ también disparan publicación. En caso de trabajo paralelo sin confirmar en archivos distintos, --committed-only permite publicar únicamente el commit exacto, sin incluir ni modificar el trabajo ajeno; las rutas que coincidan bloquean el proceso. No se sincronizan por Git los ajustes personales del navegador.
