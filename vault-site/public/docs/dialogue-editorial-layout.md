# Diálogos: diseño compartido con el editor
El demo /laboratorio/dialogo/ consume el mismo web component book-editorial-dialogue que el editor /dm/libro/#ui. El escenario, personaje, texto, historial y opciones pertenecen al contenido del demo; posiciones, encuadre, escala y composición al diseño editorial. No hay un CSS de diálogo paralelo.
Al abrir o guardar un diseño de tipo diálogo, el editor registra el diseño activo y sus ajustes en el almacenamiento del mismo origen. El demo sigue ese diseño al recibir el cambio, sin reiniciar la conversación. El selector permite usar otro diseño guardado, con respaldo en los diseños base de la bóveda. Los ajustes por vista se conservan: horizontal usa escritorio y vertical usa móvil. Se mantienen las tiradas de demostración y su historial; esto no implementa ramas reales de campaña.
Alcance: sincronización en el mismo navegador/perfil/origen; no se publican los diseños privados ni se modifican permisos Firestore. La selección automática de un diseño privado entre dispositivos queda pendiente. Prueba reproducible: node scripts/test-dialogue-demo-editorial-browser.mjs (edición real, escritorio, teléfono horizontal y vertical, historial y chequeo).
